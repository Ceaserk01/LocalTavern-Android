# alpha.4 安装包打包重构

目标是缩小独立可安装 APK，保留完整本地酒馆和现有插件执行环境。没有删掉 tokenizer、图像编解码器、默认素材、npm 依赖或换成在线安装。

## 方法

alpha.3 的 ARM64 APK 为 231,491,636 字节，其中资源 ZIP 为 135,216,233 字节，未压缩原生库为 96,164,928 字节。壳层代码仅占很小部分。APK 已分 ABI，运行库也已剥离调试信息，重复剥离几乎没有收益。

alpha.4 将全部文件以内容 SHA-256 分组，相同文件相邻，生成可 seek 的 STORE ZIP，然后使用固定源码构建的 Zstandard 1.5.7、单线程 level 19、32 MiB 窗口压缩。相同内容共享压缩字典，解包后仍是相互独立的普通文件，路径及字节保持一致。手机不运行压缩器。

独立 C JNI 库只包含 Zstandard 通用和解码模块，与 Node/V8 分开加载。压缩资源先校验 SHA-256；流式解码后交给现有 SafeZip，继续验证路径、重复项、CRC、文件数量与大小。ZIP 停止读取之后还显式读到 Zstandard 帧尾，拒绝截断、错误校验和、第二帧与尾随数据。只有完整验证后才写入 ready 标记并原子切换目录。外部插件／备份仍使用原 ZIP 格式和原导入流程。

Android 安装器负责解压压缩存储的原生 ELF 库。这降低下载 APK 的体积，但会保留解压后的原生库副本；需要分别报告 APK、原生库、运行文件及缓存，不能把下载节省量直接当作安装空间或运行内存节省量。Android 官方说明见[原生库打包文档](https://developer.android.com/guide/practices/page-sizes#compress-shared-libraries)。

## 完整资源压缩对照

同一份 alpha.3 文件集，20,907 个普通文件，356,720,699 字节内容：

| 格式 | 压缩字节数 |
| --- | ---: |
| alpha.3 独立 DEFLATE ZIP | 135,216,233 |
| STORE ZIP + gzip 9 | 125,589,572 |
| 按路径排序 STORE ZIP + Zstd 19 | 76,284,471 |
| 相同内容相邻 STORE ZIP + Zstd 19（固定源码构建的压缩器） | 71,057,286 |

最终方案的资源节省 47.45%。对照实验逐一检查全部路径、大小、CRC 和 SHA-256 相同。构建机的编码／解码耗时不能代表小米 15 实机速度。

## 验证范围

打包不改变原 JavaScript 模块路径、Node/V8 功能或扩展导入方式。alpha.3 已测酒馆助手 4.11.3 的功能证据仍有明确版本范围；完整资源与 alpha.3 全部 20,907 个文件已逐字节摘要比对一致，主机上已通过实际 JNI 解码器异常输入测试、ONNX SIMD／scalar 推理、tiktoken 和后端 API／SSE 回归。实际 APK 覆盖升级、安装空间和本地服务验证结果在发行附件中记录。所有自定义插件以及小米 15 实机性能仍需对应环境验证。
